# `data-*` Attributes

## What Are `data-*` Attributes?

`data-*` attributes let you embed custom metadata directly on HTML elements. The `*` is a placeholder for any name you choose.

```html
<button data-user-id="42" data-role="admin">Delete</button>
<div class="card" data-status="active" data-priority="high"></div>
```

They're part of the HTML spec, so browsers treat them as inert — no visual effect, no side effects. They exist purely to carry data.

## Why They Exist

Before `data-*`, developers had no clean way to attach extra info to elements. Common hacks:

```html
<!-- abusing class for state -->
<div class="card user-42 role-admin"></div>

<!-- abusing title or rel -->
<a rel="user-42" href="...">Profile</a>

<!-- hidden inputs or global JS objects -->
<input type="hidden" value="42">
```

These were fragile, hard to query, and semantically wrong. `data-*` gives a **spec-compliant, structured** alternative.

---

## Accessing via `getAttribute` / `setAttribute`

```javascript
const card = document.querySelector('.card');

// Read
const userId = card.getAttribute('data-user-id'); // '42'
const status  = card.getAttribute('data-status');  // 'active'

// Write
card.setAttribute('data-loaded', 'true');
card.setAttribute('data-count', 0); // stored as string '0'

// Delete
card.removeAttribute('data-status');

// Check existence
card.hasAttribute('data-loaded'); // true
```

---

## Accessing via `dataset` (Preferred)

The `dataset` property gives you a `DOMStringMap` — a live object that maps all `data-*` attributes on the element.

```javascript
const card = document.querySelector('.card');

// Read — hyphen-case → camelCase
card.dataset.userId     // data-user-id  → userId
card.dataset.status     // data-status   → status
card.dataset.isActive   // data-is-active → isActive

// Write — camelCase → hyphen-case
card.dataset.loaded      = 'true';        // sets data-loaded="true"
card.dataset.lastUpdated = '2024-01-15';  // sets data-last-updated="2024-01-15"

// Delete
delete card.dataset.status; // removes data-status
```

---

## Iterating Over All Data Attributes

```javascript
const el = document.querySelector('[data-user-id]');

// Loop over all data-* attributes
for (const [key, value] of Object.entries(el.dataset)) {
  console.log(key, value); // camelCase key, string value
}
```

## Gotchas

### Values Are Always Strings

`data-*` values are always stored as strings. Parse explicitly when needed:

```javascript
el.dataset.count = 42;
typeof el.dataset.count; // 'string'

// Numbers
const count = Number(el.dataset.count);

// Booleans
const active = el.dataset.isActive === 'true';

// Objects — store as JSON
el.dataset.config = JSON.stringify({ theme: 'dark' });
const config = JSON.parse(el.dataset.config);
```

### Null vs Empty String

```javascript
// Non-existent attribute returns null (via getAttribute)
el.getAttribute('data-missing'); // null

// Present but empty returns empty string
// <div data-empty="">
el.getAttribute('data-empty'); // ''

// dataset returns undefined for missing keys
el.dataset.missing; // undefined

// Always check with hasAttribute when the distinction matters
if (el.hasAttribute('data-value')) {
  const value = el.getAttribute('data-value');
}
```

### Setting Many Attributes at Once

```javascript
// ❌ Multiple setAttribute calls — separate DOM operations
el.setAttribute('data-a', '1');
el.setAttribute('data-b', '2');
el.setAttribute('data-c', '3');

// ✅ Use Object.assign on dataset — cleaner
Object.assign(el.dataset, { a: '1', b: '2', c: '3' });
```
