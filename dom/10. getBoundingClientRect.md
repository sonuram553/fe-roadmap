**`getBoundingClientRect()`** returns the size and position of an element relative to the **viewport** (not the document).

## What it returns

A `DOMRect` object with these properties:

```javascript
{
  top:    124,   // distance from top of viewport
  left:   50,    // distance from left of viewport
  right:  250,   // left + width
  bottom: 174,   // top + height
  width:  200,   // element's rendered width
  height: 50,    // element's rendered height
  x:      50,    // same as left
  y:      124    // same as top
}
```

## Key points

**1. Relative to viewport, not the page**
If you scroll down, `top` changes — because it's measuring distance from the current visible top of the screen, not from the top of the document.

```javascript
// To get position relative to the full document:
const rect = el.getBoundingClientRect();
const absoluteTop = rect.top + window.scrollY;
const absoluteLeft = rect.left + window.scrollX;
```

**2. Includes padding and border, not margin**
The box measured is the border-box — padding and border are included, but margin is not.

**3. Values can be negative or fractional**
If an element is scrolled above the viewport, `top` will be negative. Values are also subpixel-accurate (floats, not integers).

**4. It forces a reflow**
Calling this triggers layout recalculation if the DOM was just changed (this is why reading it repeatedly in a loop, e.g. inside `forEach`, can cause "layout thrashing" — a common performance gotcha).

```javascript
// Bad: forces reflow on every iteration
elements.forEach(el => {
  el.style.width = '100px';
  console.log(el.getBoundingClientRect().width); // reflow each time
});
```

## Common use cases

**Check if element is in viewport:**
```javascript
function isInViewport(el) {
  const rect = el.getBoundingClientRect();
  return (
    rect.top >= 0 &&
    rect.left >= 0 &&
    rect.bottom <= window.innerHeight &&
    rect.right <= window.innerWidth
  );
}
```

**Position a tooltip/dropdown relative to another element:**
```javascript
const triggerRect = trigger.getBoundingClientRect();
tooltip.style.top = `${triggerRect.bottom + 8}px`;
tooltip.style.left = `${triggerRect.left}px`;
```

**Drag-and-drop coordinate math**, **scroll-triggered animations**, and **collision detection** are other common cases.

One gotcha worth knowing: for inline elements that wrap across multiple lines, `getBoundingClientRect()` returns a rect that bounds *all* the line fragments — which can look surprising (e.g. `width` spanning the full container even though the text itself is short on the last line). If you need each fragment's own box, use `getClientRects()` instead, which returns one `DOMRect` per line box.
