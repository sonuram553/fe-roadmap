# Forms

A form is a container that collects user input into a **form data set** (name/value pairs) and sends it somewhere — either to a server (default browser behaviour) or to your own JavaScript.

```html
<form action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required />

  <label for="pwd">Password</label>
  <input id="pwd" name="pwd" type="password" />

  <button type="submit">Sign up</button>
</form>
```

Three things drive the whole mechanism:

| Attribute | Answers                          | Default                             |
| --------- | -------------------------------- | ----------------------------------- |
| `action`  | **Where** does the data go?      | The current page URL                |
| `method`  | **How** is it sent?              | `get`                               |
| `enctype` | **In what format** is it packed? | `application/x-www-form-urlencoded` |

---

## The `name` Attribute Is What Matters

A control needs a non-empty `name` to contribute its value to the form data set — but a name alone is not enough. It must also be a **successful control**: enabled, and actually "on" in the case of checkboxes and radios (see [Building the Form Data Set](#building-the-form-data-set)).

`id` is for labels and CSS/JS lookup — it never appears in submitted data.

```html
<input id="email" name="email" />
<!-- submitted as email=... -->
<input id="phone" />
<!-- no name → not submitted -->
<input name="" />
<!-- empty name → not submitted -->
<input name="city" disabled />
<!-- has a name, but disabled → not submitted -->
```

The name becomes the key the server reads (`req.body.email` in Express, `request.form["email"]` in Flask, etc.).

---

## action

The URL that receives the data.

```html
<!-- relative to the current origin -->
<form action="/signup"></form>

<!-- absolute (cross-origin allowed) -->
<form action="https://api.example.com/signup"></form>

<!-- empty: submits back to the current URL -->
<form action=""></form>

<!-- omitted: same as action="" -->
<form></form>
```

Notes:

- With `method="get"`, any existing query string in `action` is **discarded** and replaced by the form data.
- A submit button can override it with `formaction` (see [Per-Button Overrides](#per-button-overrides)).
- The property `form.action` reads back the **resolved absolute URL**, not the literal attribute. Use `form.getAttribute("action")` for the raw value.

---

## method

How the request is made. Only two values send a request.

| Method | Request | Data goes in     | Use for                              |
| ------ | ------- | ---------------- | ------------------------------------ |
| `get`  | `GET`   | URL query string | Searches, filters — idempotent reads |
| `post` | `POST`  | Request body     | Anything that changes state, uploads |

Anything else (`put`, `delete`, …) is **not** supported by HTML forms — invalid values silently fall back to `get`. To use other verbs you must submit via `fetch`.

### GET

```html
<form action="/search" method="get">
  <input name="q" value="dom events" />
  <input name="page" value="2" />
  <button>Search</button>
</form>
```

Navigates to:

```
/search?q=dom+events&page=2
```

- Data is visible in the URL, bookmarkable, shareable, and stored in browser history.
- Length is capped by browser/server URL limits (~2000 chars is the safe bound).
- Never use for passwords or anything sensitive.
- `enctype` is ignored — it is always URL-encoded.

### POST

```html
<form action="/signup" method="post">
  <input name="email" value="a@b.com" />
  <input name="pwd" value="secret" />
</form>
```

Sends:

```
POST /signup
Content-Type: application/x-www-form-urlencoded

email=a%40b.com&pwd=secret
```

- Data is in the body, not the URL — not bookmarkable, not in history.
- No practical size limit (server-configured).
- Reloading a POST result page triggers the "Confirm Form Resubmission" prompt.
- **Not encrypted** — POST is only "safer" than GET because it stays out of URLs and logs. Use HTTPS for actual protection.

## enctype

How the body is encoded. Only applies to `method="post"`.

| Value                               | Body looks like                | Use for               |
| ----------------------------------- | ------------------------------ | --------------------- |
| `application/x-www-form-urlencoded` | `a=1&b=hello+world` (default)  | Plain text fields     |
| `multipart/form-data`               | MIME parts with boundaries     | **File uploads**      |
| `text/plain`                        | `a=1\r\nb=hello world`         | Debugging only        |

```html
<form action="/upload" method="post" enctype="multipart/form-data">
  <input type="file" name="avatar" />
  <input name="caption" />
  <button>Upload</button>
</form>
```

Body:

```
Content-Type: multipart/form-data; boundary=----X

------X
Content-Disposition: form-data; name="avatar"; filename="me.png"
Content-Type: image/png

<binary bytes>
------X
Content-Disposition: form-data; name="caption"

hello
------X--
```

**Gotcha:** forget `enctype="multipart/form-data"` on a file input and the server receives only the **filename** as a string, not the file.

## What Triggers a Submission

1. Clicking a `<button>` (default `type` is `submit`), `<button type="submit">`, or `<input type="submit">`.
2. **Implicit submission** — pressing <kbd>Enter</kbd> in a single-line text field, if the form has a submit button or exactly one text field.
3. `form.requestSubmit()` from JavaScript.
4. `form.submit()` from JavaScript — but this **skips validation and the `submit` event** (see below).

Buttons have three types, and the default trips people up:

```html
<button>Submits!</button>
<!-- type="submit" is the default -->
<button type="submit">Submits</button>
<button type="reset">Resets all fields to defaults</button>
<button type="button">Does nothing — for JS handlers</button>
```

A plain `<button onclick="doThing()">` inside a form will also submit and reload the page. Use `type="button"`.

## Building the Form Data Set

At submit time the browser walks the form and collects **successful controls**. A control is excluded when it:

- has no `name`
- is `disabled` (`readonly` fields **are** submitted)
- is an unchecked checkbox or radio
- is a non-submitter `<button>` / `<input type="submit">`
- is inside a `<fieldset disabled>`

Per-control behaviour:

```html
<!-- Checkbox: absent when unchecked; value defaults to the string "on" -->
<input type="checkbox" name="terms" />
<!-- checked → terms=on -->
<input type="checkbox" name="terms" value="yes" />
<!-- checked → terms=yes -->

<!-- Radio: same name = one group, only the checked one is sent -->
<input type="radio" name="plan" value="free" checked />
<input type="radio" name="plan" value="pro" />
<!-- plan=free -->

<!-- Multi-select / repeated names: the key appears multiple times -->
<select name="tags" multiple>
  <option value="a" selected>A</option>
  <option value="b" selected>B</option>
</select>
<!-- tags=a&tags=b -->

<!-- Number/date inputs still submit strings -->
<input type="number" name="age" value="30" />
<!-- age="30", not 30 -->
```

Because unchecked checkboxes send nothing, servers must treat "key missing" as `false`. The classic workaround is a hidden field before the checkbox:

```html
<input type="hidden" name="subscribe" value="off" />
<input type="checkbox" name="subscribe" value="on" />
<!-- unchecked → subscribe=off ; checked → subscribe=off&subscribe=on (last wins in most frameworks) -->
```

## target

Where the response is displayed.

```html
<form target="_self"></form>
<!-- default: same frame -->
<form target="_blank"></form>
<!-- new tab -->
<form target="myIframe"></form>
<!-- named iframe — the pre-AJAX way to submit without a full page reload -->
```

## Per-Button Overrides

A submit button can override the form's settings — useful for one form with "Save" and "Save and publish" actions.

```html
<form action="/posts" method="post">
  <input name="title" />

  <button>Save</button>
  <button formaction="/posts/publish">Publish</button>
  <button formnovalidate formaction="/posts/draft">Save draft</button>
</form>
```

| Button attribute | Overrides |
| ---------------- | --------- |
| `formaction`     | `action`  |
| `formmethod`     | `method`  |
| `formenctype`    | `enctype` |
| `formtarget`     | `target`  |
| `formnovalidate` | Skips validation for this submission |

## The submit Event

Fires on the **form**, not the button, and is cancelable. This is where you take over.

```javascript
const form = document.querySelector("#signup");

form.addEventListener("submit", function (event) {
  event.preventDefault(); // stop the browser navigating away

  const data = new FormData(form);
  fetch("/api/signup", { method: "POST", body: data });
});
```

Key points:

- `submit` bubbles, so you can delegate: `document.addEventListener("submit", handler)`.
- It fires **after** built-in validation passes. An invalid form never reaches your handler.
- `event.submitter` is the button that caused the submission — how you tell multiple buttons apart.

```javascript
form.addEventListener("submit", (event) => {
  event.preventDefault();
  if (event.submitter.value === "publish") publish();
  else saveDraft();
});
```

### Related Events

| Event      | Fires on   | Notes                                                  |
| ---------- | ---------- | ------------------------------------------------------ |
| `submit`   | form       | Cancelable; skipped by `form.submit()`                 |
| `reset`    | form       | Cancelable; restores each control's default value      |
| `formdata` | form       | After the data set is built — last chance to mutate it |
| `invalid`  | control    | Per-field when constraint validation fails; doesn't bubble |
| `input`    | control    | Every keystroke / value change                         |
| `change`   | control    | Text fields: on blur if value changed. Checkbox/radio/select: immediately |

`formdata` lets you inject values without hidden inputs:

```javascript
form.addEventListener("formdata", (event) => {
  event.formData.append("clientTime", "2026-08-02T10:00:00Z");
});
```

## submit() vs requestSubmit()

```javascript
form.submit(); // Submits immediately.
// - Skips constraint validation
// - Does NOT fire the submit event (your handler never runs)

form.requestSubmit(); // Acts exactly like a user clicking submit.
// - Runs validation
// - Fires the submit event (so preventDefault still works)

form.requestSubmit(publishButton); // Submit as if that button was clicked
```

**Prefer `requestSubmit()`.** `form.submit()` bypassing your own `submit` handler is a common source of "my validation didn't run" bugs.

Also note: an input named `submit` shadows the method (`form.submit` becomes the element), breaking `form.submit()`. Avoid `name="submit"`.

## FormData

The bridge between the DOM form and a network request.

```javascript
const data = new FormData(form); // snapshot of all successful controls
const data2 = new FormData(form, submitButton); // include that submitter's name/value
const empty = new FormData(); // build one by hand
```

### Reading and Writing

```javascript
data.get("email"); // first value, or null
data.getAll("tags"); // ["a", "b"] — all values for a repeated key
data.has("terms"); // boolean
data.append("role", "admin"); // adds (keeps existing)
data.set("role", "user"); // replaces all existing
data.delete("pwd");

for (const [key, value] of data) {
  console.log(key, value);
}
```

### Converting

```javascript
// To a plain object — NOTE: loses repeated keys, keeps only the last
const obj = Object.fromEntries(data);

// To JSON, preserving multi-value keys
const obj2 = {};
for (const [k, v] of data) {
  if (k in obj2) obj2[k] = [].concat(obj2[k], v);
  else obj2[k] = v;
}

// To a query string
const qs = new URLSearchParams(data).toString(); // "q=dom&page=2"
```

### Sending

```javascript
// multipart/form-data — browser sets Content-Type + boundary automatically
fetch("/api/upload", { method: "POST", body: data });

// urlencoded
fetch("/api/signup", {
  method: "POST",
  body: new URLSearchParams(data),
});

// JSON
fetch("/api/signup", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(Object.fromEntries(data)),
});
```

**Never set `Content-Type` manually when the body is a `FormData`** — you'd omit the multipart boundary and the server can't parse it.

## Client-Side Validation

The browser validates before firing `submit`.

```html
<input name="email" type="email" required />
<input name="age" type="number" min="18" max="120" />
<input name="user" pattern="[a-z0-9]{3,16}" title="3–16 lowercase letters/digits" />
<input name="bio" maxlength="200" minlength="10" />
<textarea name="notes" required></textarea>
```

Turn it off with `novalidate` on the form or `formnovalidate` on a button.

### Validation API

```javascript
input.validity.valid; // overall
input.validity.valueMissing; // failed `required`
input.validity.typeMismatch; // bad email/url
input.validity.patternMismatch; // failed `pattern`
input.validity.tooShort / tooLong / rangeUnderflow / rangeOverflow;
input.validity.customError;

input.validationMessage; // the browser's message string

form.checkValidity(); // boolean, fires `invalid` events, shows nothing
form.reportValidity(); // same + displays the native error bubble
```

### Custom Rules

```javascript
const confirmPwd = form.elements.confirmPwd;

confirmPwd.addEventListener("input", () => {
  confirmPwd.setCustomValidity(
    confirmPwd.value === form.elements.pwd.value ? "" : "Passwords do not match",
  );
});
```

An empty string clears the error; any non-empty string makes the field invalid.

### Styling

```css
input:required { }
input:invalid { border-color: red; }         /* applies immediately, even before typing */
input:user-invalid { border-color: red; }    /* only after the user has interacted — prefer this */
input:valid { }
```

**Client-side validation is a UX convenience, not security.** Anyone can strip it with devtools or skip the form entirely with `curl`. Always validate again on the server.

## Accessing Form Controls

```javascript
const form = document.forms.signup; // by form's name/id
const form2 = document.forms[0];

form.elements.email; // by control name — the reliable way
form.elements["email"];
form.elements.namedItem("email");
form.elements.length; // all controls
[...form.elements]; // array of controls

form.email.value; // shorthand (works, but collides with form properties)
form.reset(); // restore defaults
```

Radio groups return a `RadioNodeList`; `.value` gives the checked one:

```javascript
form.elements.plan.value; // "free"
```

## Controls Outside the Form

The `form` attribute associates a control with a form anywhere in the document — useful when layout prevents nesting.

```html
<form id="checkout" action="/pay" method="post"></form>

<input name="coupon" form="checkout" />
<button form="checkout">Pay</button>
```

## Grouping and Disabling

```html
<fieldset disabled>
  <legend>Billing address</legend>
  <input name="street" />
  <!-- disabled → not submitted -->
</fieldset>
```

Disabling the `<fieldset>` disables and excludes every control inside it in one move.

## Autocomplete

```html
<form autocomplete="on">
  <input name="email" autocomplete="email" />
  <input name="pwd" type="password" autocomplete="current-password" />
  <input name="newPwd" type="password" autocomplete="new-password" />
  <input name="otp" autocomplete="one-time-code" />
  <input name="cardNo" autocomplete="cc-number" />
  <input name="search" autocomplete="off" />
</form>
```

Correct `autocomplete` tokens let password managers and browser autofill work properly — a real accessibility and conversion win, not just a nicety.

## Full Example: Progressive Enhancement

The form works without JavaScript, and JS upgrades it to an in-page submission.

```html
<form id="signup" action="/signup" method="post">
  <label for="email">Email</label>
  <input id="email" name="email" type="email" required autocomplete="email" />

  <label for="pwd">Password</label>
  <input
    id="pwd"
    name="pwd"
    type="password"
    required
    minlength="8"
    autocomplete="new-password"
  />

  <label><input type="checkbox" name="terms" required /> I accept the terms</label>

  <button>Create account</button>
  <p id="status" role="status"></p>
</form>
```

```javascript
const form = document.getElementById("signup");
const status = document.getElementById("status");

form.addEventListener("submit", async (event) => {
  event.preventDefault();

  const button = event.submitter;
  button.disabled = true;
  status.textContent = "Creating account…";

  try {
    const res = await fetch(form.action, {
      method: form.method,
      headers: { Accept: "application/json" },
      body: new FormData(form),
    });

    if (!res.ok) throw new Error(await res.text());

    status.textContent = "Account created";
    form.reset();
  } catch (err) {
    status.textContent = `Failed: ${err.message}`;
  } finally {
    button.disabled = false;
  }
});
```

Disabling the button inside the handler (not before) prevents double submission without breaking the no-JS path.

## Common Gotchas

| Problem                                     | Cause                                                  |
| ------------------------------------------- | ------------------------------------------------------ |
| Page reloads on button click                | `<button>` defaults to `type="submit"` — use `type="button"` |
| Field missing on the server                 | No `name` attribute, or the control is `disabled`      |
| File arrives as a filename string           | Missing `enctype="multipart/form-data"`                |
| Checkbox key absent from the payload        | Unchecked checkboxes are not submitted at all          |
| `submit` handler never runs                 | Called `form.submit()` instead of `form.requestSubmit()` |
| Multipart body rejected by the server       | Manually set `Content-Type` on the `fetch`             |
| Enter key submits unexpectedly              | Implicit submission — add `type="button"` or handle `keydown` |
| `Object.fromEntries(formData)` drops values | Repeated keys collapse — use `getAll()`                |
| `form.submit is not a function`             | A control is named `submit`, shadowing the method      |
| Validation styles show before typing        | Use `:user-invalid` instead of `:invalid`              |

## Quick Reference

```html
<form
  action="/endpoint"
  method="post"
  enctype="multipart/form-data"
  target="_self"
  novalidate
  autocomplete="on"
  name="signup"
></form>
```

| Attribute      | Meaning                                                 |
| -------------- | ------------------------------------------------------- |
| `action`       | Where the data goes (defaults to the current URL)       |
| `method`       | `get` \| `post`                                         |
| `enctype`      | How the body is packed — `post` only                    |
| `target`       | Where the response renders                              |
| `novalidate`   | Skip built-in validation                                |
| `autocomplete` | `on` / `off` for the whole form                         |
| `name`         | Looks the form up via `document.forms.signup`           |
