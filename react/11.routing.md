# React Routing

Routing in React enables **single-page applications (SPAs)** where different components render based on the URL path, without page reloads.

## Router Types

React Router provides different router types for different environments:

### BrowserRouter (Recommended)

It uses the browser's built-in History API to handle navigation, which allows for clean, readable URLs (e.g., www.example.com/about). This is the router you'll use in most public-facing, client-side React applications because it's the expected behavior for a modern website.

It directly interacts with the browser's history stack. Navigating to a new route pushes a new entry onto the history stack, so the back and forward buttons work as expected

```jsx
import { BrowserRouter } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}
```

**Why server config is needed?**

With BrowserRouter, URLs like `/about` are **sent to the server**. When you visit `example.com/about`:

1. Browser requests `example.com/about` from server
2. Server looks for a file at `/about` (doesn't exist)
3. **Without proper config**: Server returns 404 error
4. **With proper config**: Server returns index.html, letting React Router handle routing

**Server configuration examples:**

```javascript
const express = require("express");
const path = require("path");
const app = express();
const PORT = process.env.PORT || 3000;

// Middleware for parsing JSON
app.use(express.json());

// API routes (handle these before React routes)
app.get("/api/users", (req, res) => {
  res.json([
    { id: 1, name: "John" },
    { id: 2, name: "Jane" },
  ]);
});

app.post("/api/users", (req, res) => {
  // Handle user creation
  res.json({ message: "User created" });
});

// Serve static files from React build
app.use(express.static(path.join(__dirname, "build")));

// Handle React routing, return all requests to React app
app.get("*", (req, res) => {
  res.sendFile(path.join(__dirname, "build", "index.html"));
});

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

**Express.js with HashRouter (Simpler):**

```javascript
const express = require("express");
const path = require("path");
const app = express();
const PORT = process.env.PORT || 3000;

// Middleware for parsing JSON
app.use(express.json());

// API routes
app.get("/api/users", (req, res) => {
  res.json([
    { id: 1, name: "John" },
    { id: 2, name: "Jane" },
  ]);
});

// Serve static files from React build
app.use(express.static(path.join(__dirname, "build")));

// No catch-all route needed! Server only handles /api/* and static files
// HashRouter handles all client-side routing

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

**Key Difference:**

- **BrowserRouter**: Needs `app.get("*", ...)` to handle direct URL access
- **HashRouter**: No catch-all needed - server only handles API and static files

**Pros:**

- Clean URLs: `/about` instead of `/#/about`
- Better SEO
- Server-side rendering friendly

**Cons:**

- Requires server configuration for direct URL access
- Not supported in older browsers

### HashRouter

Uses URL hash for routing, works without server configuration.

```jsx
import { HashRouter } from "react-router-dom";

function App() {
  return (
    <HashRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </HashRouter>
  );
}
```

**Why no server config needed?**

The hash (`#`) part of the URL is **never sent to the server**. When you visit `example.com/#/about`:

1. Browser requests `example.com/` from server
2. Server returns the main HTML file (index.html)
3. Browser loads the JavaScript bundle
4. React Router reads the hash (`#/about`) and renders the correct component

**URL breakdown:**

- `example.com/` → Server handles this (returns index.html)
- `#/about` → Browser handles this (never sent to server)

**Pros:**

- Works without server configuration
- Compatible with all browsers
- No 404 issues on page refresh

**How It's Different from BrowserRouter:**

The key distinction lies in how they handle the URL and interact with the server.

**URL Format:** A HashRouter creates URLs with a hash symbol, like `example.com/#/about`. A BrowserRouter creates cleaner URLs without the hash, like `example.com/about`.

**Server Configuration:** Since the hash and everything after it are never sent to the server, a HashRouter doesn't require any special server configuration. It works out of the box with static file servers because the server always receives a request for the same page (e.g., `index.html`), and the JavaScript then handles the routing. A BrowserRouter requires the server to be configured to handle all possible routes by redirecting them back to the application's single entry point, typically `index.html`, to prevent 404 errors.

### MemoryRouter

For testing or non-browser environments. Creates an in-memory history stack that doesn't affect the browser URL.

**How it works:**

- Manages its own history stack in memory
- URL in browser address bar remains unchanged
- Perfect for testing and non-browser environments

**Key props:**

- **initialEntries**: Array of URLs to start with (e.g., `["/", "/about"]`)
- **initialIndex**: Which entry to start on (default: 0)

```jsx
import { MemoryRouter } from "react-router-dom";

function App() {
  return (
    <MemoryRouter initialEntries={["/", "/about"]} initialIndex={0}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </MemoryRouter>
  );
}
```

## Core Components

### Navigation

```jsx
import { Link, NavLink, useNavigate } from 'react-router-dom';

// Declarative navigation
<Link to="/about">About</Link>
<NavLink to="/contact" className={({ isActive }) => isActive ? 'active' : ''}>
  Contact
</NavLink>

// Programmatic navigation
function LoginForm() {
  const navigate = useNavigate();

  const handleSubmit = () => {
    // Login logic...
    navigate('/dashboard');
  };
}
```

### Route Parameters

```jsx
import { useParams, useSearchParams } from "react-router-dom";

// URL parameters
function UserDetail() {
  const { id } = useParams(); // Gets id from /users/:id
  return <div>User {id}</div>;
}

// Query parameters
function ProductList() {
  const [searchParams, setSearchParams] = useSearchParams();
  const category = searchParams.get("category");

  const updateFilter = (newCategory) => {
    setSearchParams({ category: newCategory });
  };
}
```

## Nested Routes

```jsx
function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Layout />}>
          <Route index element={<Home />} />
          <Route path="users" element={<Users />}>
            <Route index element={<UserList />} />
            <Route path=":id" element={<UserDetail />} />
          </Route>
        </Route>
      </Routes>
    </BrowserRouter>
  );
}

function Layout() {
  return (
    <div>
      <Navigation />
      <main>
        <Outlet /> {/* Renders child routes */}
      </main>
    </div>
  );
}
```

## Protected Routes

```jsx
function ProtectedRoute({ children }) {
  const isAuthenticated = useAuth();
  const navigate = useNavigate();

  useEffect(() => {
    if (!isAuthenticated) {
      navigate("/login", { replace: true });
    }
  }, [isAuthenticated, navigate]);

  return isAuthenticated ? children : null;
}

// Usage
<Route
  path="/dashboard"
  element={
    <ProtectedRoute>
      <Dashboard />
    </ProtectedRoute>
  }
/>;
```

## Key Hooks

- **useNavigate()** - Programmatic navigation
- **useParams()** - URL parameters
- **useSearchParams()** - Query parameters
- **useLocation()** - Current location info
- **useOutlet()** - Current outlet element
