JSX isn't valid JavaScript on its own — it's compiled by Babel into plain JS function calls before it ever reaches the browser. This is what "JSX compiles to `React.createElement` calls" means, and it's the reason a build step (Babel/TypeScript) is required to use JSX at all.

## Classic Runtime (pre-React 17)

Each JSX tag becomes a `React.createElement(type, props, ...children)` call.

```jsx
// JSX in
function Greeting({ name }) {
  return <h1 className="title">Hello, {name}!</h1>;
}

const list = (
  <ul>
    {items.map((item) => (
      <li key={item.id}>{item.name}</li>
    ))}
  </ul>
);
```

```javascript
// Compiles to (Classic runtime)
function Greeting({ name }) {
  return /*#__PURE__*/ React.createElement(
    "h1",
    { className: "title" },
    "Hello, ",
    name,
    "!"
  );
}

const list = /*#__PURE__*/ React.createElement(
  "ul",
  null,
  items.map((item) =>
    /*#__PURE__*/ React.createElement("li", { key: item.id }, item.name)
  )
);
```

Because every file using JSX needed `React.createElement`, every file had to `import React from 'react'` even if `React` was never referenced directly in the code.

## Automatic Runtime (React 17+)

Modern tooling (Vite, Next.js, current Create React App) defaults to the **automatic** JSX runtime instead. It auto-imports a `jsx`/`jsxs` helper from `react/jsx-runtime`, so the `import React` boilerplate is no longer needed just to use JSX.

```javascript
// Compiles to (Automatic runtime)
import { jsx as _jsx } from "react/jsx-runtime";

function Greeting({ name }) {
  return /*#__PURE__*/ _jsx("h1", {
    className: "title",
    children: ["Hello, ", name, "!"],
  });
}
```

Both runtimes produce equivalent UI trees — they just differ in how the element-creation call is generated and imported.

## Try it yourself

[babeljs.io/repl](https://babeljs.io/repl) lets you paste JSX on the left and see the compiled output live on the right, with the `react` preset enabled by default.

- Left panel → **OPTIONS** → **React Runtime**: toggle between `Automatic` and `Classic` to see both outputs for the same JSX.
- `Automatic` is the current default in most starter templates.
- `Classic` is what you'll see in older codebases or tutorials still using `React.createElement` directly.
