# Render Props and Higher-Order Components (HOCs) in React

## Overview

Both Render Props and Higher-Order Components (HOCs) are advanced patterns in React for sharing logic between components. They solve the same problem - code reuse and logic sharing - but with different approaches.

## Render Props Pattern

### What are Render Props?

Render props is a pattern where a component receives a function as a prop and calls that function to render something. The function receives data or state from the component and returns JSX.

### Basic Syntax

```jsx
<Component render={(data) => <ChildComponent data={data} />} />
```

### Example: Mouse Tracker with Render Props

```jsx
import React, { useState, useEffect } from "react";

// Component with render prop
function MouseTracker({ render }) {
  const [mousePosition, setMousePosition] = useState({ x: 0, y: 0 });

  useEffect(() => {
    const handleMouseMove = (event) => {
      setMousePosition({
        x: event.clientX,
        y: event.clientY,
      });
    };

    window.addEventListener("mousemove", handleMouseMove);
    return () => window.removeEventListener("mousemove", handleMouseMove);
  }, []);

  // Call the render function with the mouse position
  return render(mousePosition);
}

// Usage
function App() {
  return (
    <div>
      <MouseTracker
        render={({ x, y }) => (
          <div>
            <h1>Mouse Position</h1>
            <p>
              X: {x}, Y: {y}
            </p>
          </div>
        )}
      />

      {/* Different usage of the same component */}
      <MouseTracker
        render={({ x, y }) => (
          <div
            style={{
              position: "absolute",
              left: x,
              top: y,
              width: 20,
              height: 20,
              backgroundColor: "red",
              borderRadius: "50%",
            }}
          />
        )}
      />
    </div>
  );
}
```

### Example: Data Fetcher with Render Props

```jsx
import React, { useState, useEffect } from "react";

function DataFetcher({ url, render }) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        setLoading(true);
        const response = await fetch(url);
        const result = await response.json();
        setData(result);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    };

    fetchData();
  }, [url]);

  return render({ data, loading, error });
}

// Usage
function UserList() {
  return (
    <DataFetcher
      url="https://jsonplaceholder.typicode.com/users"
      render={({ data, loading, error }) => {
        if (loading) return <div>Loading...</div>;
        if (error) return <div>Error: {error}</div>;
        if (!data) return <div>No data</div>;

        return (
          <ul>
            {data.map((user) => (
              <li key={user.id}>{user.name}</li>
            ))}
          </ul>
        );
      }}
    />
  );
}
```

## Higher-Order Components (HOCs)

### What are HOCs?

A Higher-Order Component is a function that takes a component and returns a new component with additional props or behavior.

### Basic Syntax

```jsx
const EnhancedComponent = withHOC(BaseComponent);
```

### Example: Mouse Tracker HOC

```jsx
import React, { useState, useEffect } from "react";

// HOC function
function withMouseTracker(WrappedComponent) {
  return function MouseTrackerHOC(props) {
    const [mousePosition, setMousePosition] = useState({ x: 0, y: 0 });

    useEffect(() => {
      const handleMouseMove = (event) => {
        setMousePosition({
          x: event.clientX,
          y: event.clientY,
        });
      };

      window.addEventListener("mousemove", handleMouseMove);
      return () => window.removeEventListener("mousemove", handleMouseMove);
    }, []);

    // Pass mouse position as props to the wrapped component
    return <WrappedComponent {...props} mousePosition={mousePosition} />;
  };
}

// Base component
function MouseDisplay({ mousePosition }) {
  return (
    <div>
      <h1>Mouse Position</h1>
      <p>
        X: {mousePosition.x}, Y: {mousePosition.y}
      </p>
    </div>
  );
}

// Enhanced component
const MouseDisplayWithTracker = withMouseTracker(MouseDisplay);

// Usage
function App() {
  return <MouseDisplayWithTracker />;
}
```

### Example: Data Fetcher HOC

```jsx
import React, { useState, useEffect } from "react";

function withDataFetcher(WrappedComponent, url) {
  return function DataFetcherHOC(props) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
      const fetchData = async () => {
        try {
          setLoading(true);
          const response = await fetch(url);
          const result = await response.json();
          setData(result);
        } catch (err) {
          setError(err.message);
        } finally {
          setLoading(false);
        }
      };

      fetchData();
    }, [url]);

    return (
      <WrappedComponent
        {...props}
        data={data}
        loading={loading}
        error={error}
      />
    );
  };
}

// Base component
function UserList({ data, loading, error }) {
  if (loading) return <div>Loading...</div>;
  if (error) return <div>Error: {error}</div>;
  if (!data) return <div>No data</div>;

  return (
    <ul>
      {data.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}

// Enhanced component
const UserListWithData = withDataFetcher(
  UserList,
  "https://jsonplaceholder.typicode.com/users"
);

// Usage
function App() {
  return <UserListWithData />;
}
```

### Example: Authentication HOC

```jsx
import React from "react";

function withAuth(WrappedComponent) {
  return function AuthHOC(props) {
    const [isAuthenticated, setIsAuthenticated] = React.useState(false);
    const [user, setUser] = React.useState(null);

    React.useEffect(() => {
      // Check authentication status
      const checkAuth = () => {
        const token = localStorage.getItem("token");
        if (token) {
          setIsAuthenticated(true);
          setUser({ name: "John Doe" }); // Mock user data
        }
      };

      checkAuth();
    }, []);

    if (!isAuthenticated) {
      return <div>Please log in to continue</div>;
    }

    return <WrappedComponent {...props} user={user} />;
  };
}

function Dashboard({ user }) {
  return (
    <div>
      <h1>Welcome, {user.name}!</h1>
      <p>This is your dashboard</p>
    </div>
  );
}

const ProtectedDashboard = withAuth(Dashboard);
```

## Comparison: Render Props vs HOCs

| Aspect          | Render Props                          | Higher-Order Components            |
| --------------- | ------------------------------------- | ---------------------------------- |
| **Pattern**     | Function as prop                      | Function that returns component    |
| **Flexibility** | High - can render anything            | Limited - must return JSX          |
| **Props**       | Passed as function parameters         | Passed as component props          |
| **Composition** | Easy to compose multiple render props | Can lead to "wrapper hell"         |
| **Performance** | Can be optimized with `useMemo`       | Can be optimized with `React.memo` |
| **Debugging**   | Clear in React DevTools               | Can be harder to debug             |
| **TypeScript**  | Good type inference                   | Can be complex with generics       |

### Advantages of Render Props

✅ **Flexibility**: Can render any JSX, not just components  
✅ **Clear data flow**: Data is explicitly passed as function parameters  
✅ **Easy composition**: Multiple render props can be easily combined  
✅ **Better TypeScript support**: Function parameters are easier to type  
✅ **No wrapper hell**: Components don't get deeply nested

#### What does "Can render any JSX, not just components" mean?

This is a key advantage of render props over HOCs. Let me demonstrate:

**Render Props - Flexible JSX rendering:**

```jsx
// Render props can return ANY JSX structure
<DataFetcher
  url="/api/users"
  render={({ data, loading, error }) => {
    if (loading) return <div>Loading...</div>;
    if (error) return <div>Error: {error}</div>;

    // Can return different JSX structures based on data
    if (data.length === 0) {
      return <p>No users found</p>;
    }

    if (data.length === 1) {
      return <h2>Found 1 user: {data[0].name}</h2>;
    }

    // Can return complex JSX with conditional rendering
    return (
      <div>
        <h2>Found {data.length} users:</h2>
        <ul>
          {data.map((user) => (
            <li key={user.id}>
              {user.name} - {user.email}
            </li>
          ))}
        </ul>
        <button onClick={() => console.log("Users:", data)}>Log Users</button>
      </div>
    );
  }}
/>
```

**HOCs - Limited to component structure:**

```jsx
// HOCs must return a component, limiting flexibility
function withDataFetcher(WrappedComponent, url) {
  return function DataFetcherHOC(props) {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    // ... fetch logic

    // HOC MUST return the wrapped component
    return (
      <WrappedComponent
        {...props}
        data={data}
        loading={loading}
        error={error}
      />
    );
  };
}

// Usage - limited to the component's structure
const UserListWithData = withDataFetcher(UserList, "/api/users");
// Can only use UserList's existing structure, can't change rendering logic
```

**Key Differences:**

1. **Render Props**: The render function can return completely different JSX based on conditions
2. **HOCs**: Must always return the wrapped component with props, can't change the rendering logic

### Advantages of HOCs
  
✅ **Easy to apply to existing components**: Can wrap any component  
✅ **Good for cross-cutting concerns**: Authentication, logging, etc.  
✅ **Can modify component behavior**: Can intercept lifecycle methods (in class components)

### Disadvantages of Render Props

❌ **Performance**: Function creation on every render (can be optimized)  
❌ **Learning curve**: New pattern for many developers

### Disadvantages of HOCs

❌ **Wrapper hell**: Multiple HOCs can create deeply nested components  
❌ **Props collision**: HOCs might override props unintentionally  
❌ **Static composition**: HOC composition happens at component definition time  
❌ **Debugging**: Harder to trace through multiple wrapper components

## When to Use Each Pattern

### Use Render Props when:

- You need maximum flexibility in what gets rendered
- You want to share logic but render different UI
- You're working with TypeScript and want better type inference
- You want to avoid wrapper hell
- You need dynamic composition

### Use HOCs when:

- You want to add behavior to existing components
- You're dealing with cross-cutting concerns (auth, logging, etc.)
- You prefer a more functional programming approach
- You want to modify component behavior
- You're working with class components

## Modern Alternatives

### Custom Hooks (Recommended)

```jsx
import { useState, useEffect } from "react";

// Custom hook instead of render props or HOC
function useMousePosition() {
  const [mousePosition, setMousePosition] = useState({ x: 0, y: 0 });

  useEffect(() => {
    const handleMouseMove = (event) => {
      setMousePosition({
        x: event.clientX,
        y: event.clientY,
      });
    };

    window.addEventListener("mousemove", handleMouseMove);
    return () => window.removeEventListener("mousemove", handleMouseMove);
  }, []);

  return mousePosition;
}

// Usage
function MouseDisplay() {
  const { x, y } = useMousePosition();

  return (
    <div>
      <h1>Mouse Position</h1>
      <p>
        X: {x}, Y: {y}
      </p>
    </div>
  );
}
```

## Best Practices

1. **Prefer custom hooks** over render props and HOCs when possible
2. **Use render props** when you need maximum flexibility
3. **Use HOCs** for cross-cutting concerns and authentication
4. **Consider Context API** for deeply nested data sharing
5. **Optimize performance** with `useMemo`, `useCallback`, and `React.memo`

## Conclusion

Both render props and HOCs are powerful patterns for sharing logic in React, but they serve different use cases. Render props offer more flexibility and better TypeScript support, while HOCs are great for adding behavior to existing components. However, custom hooks are often the best modern solution, offering the benefits of both patterns with less complexity.
