## What are Error Boundaries?

Error boundaries are React components that **catch JavaScript errors anywhere in their child component tree** and display a fallback UI instead of the component tree that crashed.

### Key Points

- ✅ **Catch errors** in child components
- ✅ **Display fallback UI** when errors occur
- ✅ **Log error information** for debugging
- ✅ **Prevent the entire app** from crashing
- ❌ **Don't catch errors** in event handlers
- ❌ **Don't catch errors** in async code
- ❌ **Don't catch errors** in server-side rendering

## Why Use Error Boundaries?

Without error boundaries, a JavaScript error inside a component can corrupt React's internal state and cause it to emit cryptic errors on future renders. Error boundaries help you:

1. **Prevent app crashes** - Users see a friendly error message instead of a white screen
2. **Isolate errors** - Only the problematic component tree is affected
3. **Log errors** - Capture error information for debugging
4. **Graceful degradation** - Show alternative content when components fail

## Implementation

Error boundaries must be implemented as **class components** (not functional components) because they need access to lifecycle methods.

### Basic Error Boundary

```jsx
import React from "react";

class ErrorBoundary extends React.Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null, errorInfo: null };
  }

  static getDerivedStateFromError(error) {
    // Update state so the next render will show the fallback UI
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    // Log error information
    console.error("Error caught by boundary:", error);
    console.error("Error info:", errorInfo);

    this.setState({
      error: error,
      errorInfo: errorInfo,
    });
  }

  render() {
    if (this.state.hasError) {
      return (
        <div
          style={{
            padding: "20px",
            border: "1px solid #ff6b6b",
            borderRadius: "8px",
          }}
        >
          <h2>Something went wrong.</h2>
          <details style={{ whiteSpace: "pre-wrap" }}>
            {this.state.error && this.state.error.toString()}
            <br />
            {this.state.errorInfo.componentStack}
          </details>
        </div>
      );
    }

    return this.props.children;
  }
}

export default ErrorBoundary;
```

### Usage Example

```jsx
import React from "react";
import ErrorBoundary from "./ErrorBoundary";

// Component that might throw an error
function BuggyCounter() {
  const [count, setCount] = React.useState(0);

  if (count === 5) {
    throw new Error("I crashed!");
  }

  return (
    <div>
      <h1>Count: {count}</h1>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

// Wrap the component with error boundary
function App() {
  return (
    <div>
      <h1>Error Boundary Demo</h1>
      <ErrorBoundary>
        <BuggyCounter />
      </ErrorBoundary>
    </div>
  );
}
```

## How Error Boundaries Work

Error boundaries use two lifecycle methods to catch and handle errors:

### 1. **getDerivedStateFromError(error)**

- **Called automatically** by React when a child component throws an error
- **Must return an object** to update the component's state
- **Runs during the render phase** (synchronously)
- **Cannot perform side effects** (no API calls, logging, etc.)

### 2. **componentDidCatch(error, errorInfo)**

- **Called after** `getDerivedStateFromError`
- **Safe to perform side effects** (logging, API calls, etc.)
- **Receives error details** for debugging
- **Runs during the commit phase** (after DOM updates)

**Parameters:**

- `error`: The error that was thrown
- `errorInfo`: An object containing `componentStack` (the component stack trace)

## Error Handling Flow

```
Child Component Throws Error
           ↓
React Detects Error
           ↓
getDerivedStateFromError() ← Called FIRST
           ↓
Returns { hasError: true }
           ↓
componentDidCatch() ← Called SECOND
           ↓
Log error, send to service, etc.
           ↓
render() with fallback UI
```

## Best Practices

### 1. **Placement Strategy**

```jsx
// ✅ Wrap specific sections or routes
function App() {
  return (
    <div>
      <Header />
      <ErrorBoundary>
        <MainContent />
      </ErrorBoundary>
      <Footer />
    </div>
  );
}

// ✅ Wrap individual components that might fail
function UserProfile({ userId }) {
  return (
    <ErrorBoundary>
      <UserData userId={userId} />
    </ErrorBoundary>
  );
}
```

### 2. **Multiple Error Boundaries**

```jsx
function App() {
  return (
    <div>
      <ErrorBoundary>
        <Header />
      </ErrorBoundary>

      <ErrorBoundary>
        <Sidebar />
      </ErrorBoundary>

      <ErrorBoundary>
        <MainContent />
      </ErrorBoundary>

      <ErrorBoundary>
        <Footer />
      </ErrorBoundary>
    </div>
  );
}
```

### 3. **Error Reporting Integration**

```jsx
class ErrorBoundary extends React.Component {
  componentDidCatch(error, errorInfo) {
    // Log to console in development
    if (process.env.NODE_ENV === "development") {
      console.error("Error caught by boundary:", error);
      console.error("Error info:", errorInfo);
    }

    // Send to error reporting service in production
    if (process.env.NODE_ENV === "production") {
      fetch("/api/errors", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          error: error.message,
          stack: error.stack,
          componentStack: errorInfo.componentStack,
          timestamp: new Date().toISOString(),
        }),
      });
    }
  }
}
```

## What Error Boundaries DON'T Catch

### 1. **Event Handlers**

```jsx
// ❌ Error boundaries don't catch errors in event handlers
function BuggyButton() {
  const handleClick = () => {
    throw new Error("Event handler error");
  };

  return <button onClick={handleClick}>Click me</button>;
}

// ✅ Use try-catch in event handlers
function SafeButton() {
  const handleClick = () => {
    try {
      throw new Error("Event handler error");
    } catch (error) {
      console.error("Caught error in event handler:", error);
    }
  };

  return <button onClick={handleClick}>Click me</button>;
}
```

### 2. **Asynchronous Code**

```jsx
// ❌ Error boundaries don't catch async errors
function AsyncComponent() {
  const [data, setData] = React.useState(null);

  React.useEffect(() => {
    fetch("/api/data")
      .then((response) => {
        throw new Error("Async error");
      })
      .catch((error) => {
        console.error("Async error:", error);
      });
  }, []);

  return <div>{data}</div>;
}

// ✅ Handle async errors with try-catch
function SafeAsyncComponent() {
  const [data, setData] = React.useState(null);
  const [error, setError] = React.useState(null);

  React.useEffect(() => {
    const fetchData = async () => {
      try {
        const response = await fetch("/api/data");
        if (!response.ok) {
          throw new Error("Failed to fetch data");
        }
        const result = await response.json();
        setData(result);
      } catch (error) {
        setError(error.message);
      }
    };

    fetchData();
  }, []);

  if (error) return <div>Error: {error}</div>;
  if (!data) return <div>Loading...</div>;

  return <div>{data}</div>;
}
```

## Summary

Error boundaries are essential for building robust React applications. They:

- **Catch JavaScript errors** in component trees
- **Display fallback UI** instead of crashing
- **Log error information** for debugging
- **Isolate errors** to specific parts of your app
- **Must be class components** (not functional components)
- **Don't catch** event handler or async errors

Use error boundaries strategically to provide a better user experience and make your applications more resilient to runtime errors.
